这个仓库是一个策略决策实验室：M0–M11 完成节点选择、淘汰、KVS、SLO 与 lifecycle 的仿真闭环；M12 转向 Goodput × Reuse，把 Priced Spill、Reuse-Adjusted Binpack、Decode Credits 与 cluster eviction 放进同一套多维验收。M9-HW 前只报告 NORMALIZED_WORK／normalized utilization，不报告真实毫秒或 MFU。

1. 总体架构

我们究竟在做什么：不是测 GPU 性能，而是回答"哪些缓存／调度策略组合在同一条 trace 上排序更优"。输入是固定 trace（SHA-256 b434f181…f711）与确定性随机源；输出是策略间的相对排序；明确不输出 TTFT 毫秒或 SLO 达标率。

1.1 两条口径纪律（贯穿全部里程碑）

纪律内容
命中率双口径block_ref_hit_rate 与 token_weighted_hit_rate 必须同时报，不许混在一列
goodput 严格口径主口径 strict_completed_goodput（只算完整完成）；partial_output_tokens 永远不进 goodput

2.5 M11 RFC 已定的关键决策

  • attach 点：把带版本的打分函数交付给现有版图 owner——FlexLB master 是 push 型、Turbo CacheAwareScheduler 是 pull 型；不建第三张全局图（RFC §2）。
  • WHERE 与生命周期分离：selector 只回答 WHERE（LegRoute { prefer_host, exclude_hosts, hint_input_tokens }）；LLMClientV1 保有 logical_request_id、attempt 身份、重试预算、续段、OutputAuthority（epoch + output_seq 围栏）、durable output-ack ledger（RFC §3）。
  • 四档 enforcement：off｜shadow｜enforce｜required；fail-open 五种原因计数：timeout／error／stale view／capability mismatch／planner unavailable（RFC §4–§5）。
  • 能力握手：PREFIX_CACHE_QUERY、DECODE_LEASE_V1、R2_CHECKPOINT_STORE、COOPERATIVE_PREEMPT；未握手实例按零能力对待（RFC §6）。

M12.0 实测 verdict：KILL_ROUTER_HOLD

  • trace 只有 1,180 个约 3.05s timestamp buckets，不能直接解析 250ms。
  • raw token-weighted same-bucket：52.1712%；gate 口径 same-bucket：0.1186%。
  • 用 5s window 覆盖跨 bucket 的真实 250ms pair，保守上界仍只有 0.1725%，低于 10% 约 58×。
  • 停止 router hold-and-batch；保留 Priced Spill、placement locality 与 engine continuous batching。

M12.1 metric contract v1.1 已冻结

  • Workload truth 独立于 attempts；zero-attempt drop 仍在 offered／fairness 分母。
  • 排名：combined strict goodput；input／output 分列，output 相对退化≤0.1%。
  • 全部 retry／abort GPU work 计费；KVS normalized work 进入 M12.2 completion scheduling。
  • Fairness：tier≥0.80、Jain≥0.90、相对 baseline 退化≤0.02；三套 regime 只作 sensitivity。

trace：23,608 请求，input 均值 8,589.96，output 均值 182.13。Mooncake Inf=0.51 仅作论文参照（分母与插入时机未指明）。

4. 风险与备选

不可宣称框（must-not-claim）——以下句式在任何汇报里都不允许出现

  1. ❌ "仿真显示 TTFT 降低 X ms／SLO 提升 X%"——时间单位是 NORMALIZED_WORK，无毫秒语义；带 _ms 后缀的字段同样是归一化工作量。
  2. ❌ "682 测试通过，可以上线"——测试只覆盖仿真器与 mock 链路，不含生产 E2E／canary。
  3. ❌ "M9 已完成标定"——只有 harness，calibration_status=SYNTHETIC_UNCALIBRATED。
  4. ❌ "M10 tau_b=1.0 证明排序在生产可复现"——弱证据，压力不足，需 M10-HW 重测。
  5. ❌ "S3 比 S4 好（或反之）"——两者是不同 trade-off，M4 只给 diff。
  6. ❌ "D2 抢占收益已验证"——M8 是 ASSUME_RESUME_SUCCESS_UPPER_BOUND 上界模型。
  7. ❌ "S3 比线上提升 9.71 pp"——9.71 pp 是相对 Random；相对 S5／S6 simulator baseline 只有约 0.6～1.7 pp，production headroom 未测量。

5. Rollout
